# Application update: dinosaurs, missions and rankings

The [`app-2026-11-16` application package](https://github.com/Bladestar2105/Minecraft-Ark/releases/tag/app-2026-11-16) contains ArkDinos 1.2.2 and the collected dinosaur, mission and ranking changes below. The fixed world snapshot remains `world-2026-11-06`.

## Collected changes

This package collects the November 15 work alongside the current fixes:

- **Taming:** T-Rex, Velociraptor and Dilophosaurus remain aggressive through every meat feed. Only the finishing bone tames them and stops their attacks. T-Rex still needs twelve meat feeds twenty seconds apart; Raptor and Dilo need five ten seconds apart. There is no feeding truce. Progress stays reserved to the feeder for five minutes after the latest accepted feed; an actual positive uncancelled hit from that player clears it.
- **Combat:** mounted attacks and companion melee reach the dinosaur's visible head and jaw, or the Stegosaurus tail. Following companions use the same reach when defending after a permitted attack on their owner. Dilophosaurus keeps pursuing its target while spitting, so a shot blocked by its owner does not leave it stationary. Aim at a nearby opponent and use attack; the one-second attack cooldown, line-of-sight checks and protection rules still apply.
- **Pteranodon:** mounted jump can take off from water. Owned adults in Follow can rise before unfolding their wings, accompany an owner flying on another owned Pteranodon, or reach a checked dry landing near a shorebound owner. Loaded space, collision, owner-distance and safe-flight limits still apply.
- **Eggs and models:** ordinary Creative Spawn Eggs tabs/search expose the species eggs in configured dinosaur worlds. Existing tagged eggs retain ownership and quantity. Placed nests retain their native block and gameplay data beneath their species shell. Dinosaur animations continue while viewers track the entity, including beyond the model library's shorter animation sight radius; persisted trackers receive this setting on reattachment.
- **Missions:** the pinned Quests 5.3.2 patch keeps definition/prerequisite order, shows unavailable missions in gray and explains unmet requirements. The new configuration uses `confirm-accept: false`: an explicit `/quests take <display name>` or German `/quests nehmen <display name>` accepts immediately when the native checks pass. It no longer waits for a chat `Ja`. Abandon confirmation remains enabled. Native prerequisites, item costs, objectives, rewards and saved progress remain authoritative.
- **Rankings:** ArkAtlas refreshes the spawn ranking from the current whitelist, keeping removed players out of that display while preserving their underlying progress.

Owner-only healing, compass tracking and direct private support replies from the previous application update remain included. See [dinosaur behavior](../dino-plugin/README.md), [egg resources](../dino-items/README.md) and [mission instructions](../config/quests/README.md).

## Existing installations

1. Download the selected release's ZIP and `SHA256SUMS`. Verify the ZIP and extract into a separate empty directory. Keep a restorable copy of the existing installation and stop Minecraft normally before replacing loaded files. Fresh `scripts/setup.py` is not an updater.
2. Compare the package with the installed versions and dependencies. Install the verified ArkDinos 1.2.2 and updated ArkAtlas 1.0.1 JARs, plus the package's pinned patched Quests 5.3.2 if the installed bytes differ. Keep exactly one JAR for each plugin identity, even if an old deployment used a different filename. Preserve plugin data directories, configuration, player records, inventories, worlds, permissions and private secrets.
3. For direct mission acceptance, change only the existing Quests configuration's `confirm-accept` setting to `false`; keep `confirm-abandon: true`. Preserve other local settings. Do not replace saved quest profiles or reset completed missions. Players select display names, for example `/quests nehmen Werkzeugmacher`; list numbers are not IDs. Unmet prerequisites still prevent acceptance.
4. Existing servers upgrading egg/model assets need the matching generated resource inputs and pack configuration, not just a new world archive. Follow the [egg upgrade notes](../dino-items/README.md). With the pinned GeyserModelEngine 1.0.9, retain a backup of only its generated `generated_pack/` and `generated_pack.zip` outside the generator directory before regeneration; preserve input folders, other packs and mappings. After Java pack generation, set `resource-pack-sha1` to the actual new `plugins/BetterModel/build.zip` SHA1 and use a content-versioned, player-reachable pack URL. Keep the required-pack policy. Reconnect clients and accept the updated packs.
5. Start normally and check `version ArkDinos` reports 1.2.2, that plugin loading has no duplicate identities/errors, and that existing animals and quest progress are intact. Exercise predator taming, mounted damage against a mob at the visible head, owner defense in Follow, Pteranodon water takeoff/follow, Creative egg selection and distance animations in an appropriate test area. Check both starting missions, a locked prerequisite, native item costs and the whitelist-filtered ranking without granting players artificial progress.

An application update does not replace the fixed world snapshot. Never extract a world download over a played world. These instructions do not perform a production deployment or change a server's EULA, accounts or networking.

## Verification limits

Verify the release's `SHA256SUMS` against the actual download. Use the matching source and package when reproducing behavior; an older JAR can have the same historical filename. Local Python/Java rules, protocol fixtures and browser tests cover their stated scope; they do not establish visual rendering or control acceptance on official Java, Bedrock or PS5/Switch clients. Native client/device checks remain open until performed on those clients.
