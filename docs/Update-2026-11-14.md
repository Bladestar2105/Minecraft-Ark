# Application update: dinosaur care and support replies

The `app-2026-11-14-2` application package contains ArkDinos 1.2.1, ArkSupport 1.0.2 and the longer-day pack. The fixed world download remains `world-2026-11-06`.

ArkDinos adds owner-only healing with normal food, `/dinos` with held-compass selection, feeding protection and reduced T-Rex damage, Pteranodon flight following and fish luring. Wild Pteranodons retaliate only after actual player damage and only after landing. Existing owners, creatures, worlds and inventory data remain in place. See [playing instructions](Playing.md).

ArkSupport displays the full plain-text administrator reply to its authenticated online ticket owner. Offline players read the saved answer in the portal. Operator activity pings and status notices remain conversation-free.

## Existing installations

1. Download this release's ZIP and `SHA256SUMS`, verify the ZIP, and extract into a separate directory. Fresh `setup.py` is for a new installation.
2. Stop Minecraft normally. Replace the existing ArkDinos and ArkSupport JARs with the verified 1.2.1 and 1.0.2 JARs, keeping exactly one JAR per plugin. Preserve existing plugin directories and configuration.
3. To use 30-minute daylight and roughly 10-minute nights, copy the package's `world-design/long_days` directory as `ark_long_days` into the primary world's `datapacks` directory. Its `pack.mcmeta` must be directly inside `ark_long_days`. See [the pack guide](../world-design/long_days/README.md).
4. When changing generated Java model resources, calculate the actual generated `plugins/BetterModel/build.zip` SHA1 after generation and set `resource-pack-sha1` in `server.properties` to that value. Give `resource-pack` a content-versioned URL as well. Retain the existing required-pack setting and your player-reachable host. Restart normally and reconnect to load the correct pack.
5. Confirm `version ArkDinos` reports 1.2.1 and `version ArkSupport` reports 1.0.2. Try `/dinos` on your own tamed animal, heal an injured owned animal with its primary food, and verify an administrator ticket reply while its owner is signed in.

The locator records an animal when it is loaded; animals already unloaded before installation enter the index when their area next loads. An unloaded target uses its last recorded position. Flight following requires clear, loaded space and the same world.

Automated native tests cover ownership, food consumption, compass metadata, actual chunk unload/restart, targeting, flight bounds and model packet state. They do not replace visual acceptance on official Java, Bedrock or console clients; the reported invisible Java raptor was not reproduced in those automated checks.
